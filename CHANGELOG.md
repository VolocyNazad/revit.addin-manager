# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- Markup playground (`sandbox/AddinManager.Playground`, in `AddinManager.Sandbox.slnx`): paste a XAML fragment and preview it live via `XamlReader` (element roots render, resource-dictionary roots merge into the preview).
- Collection keyboard shortcuts (v1): global `Ctrl+N` (new file), `F5`/`Ctrl+R` (refresh), `Ctrl+E` (enable/disable marked files), `Ctrl+O` (show in folder),   `Insert`/`Ctrl+Shift+N` (new entry); contextual `Delete` (delete marked rows) and `Ctrl+A` (select all/clear) scoped to the focused list — files or entries (search boxes keep their own text editing). Button tooltips name their shortcut.
- `Ctrl+U` check-for-updates shortcut (same command as the toolbar button, with the shortcut named in its tooltip).
- Editor save shortcuts: global `Ctrl+S` saves the visible detail panel of the current editor mode (form/markup/settings, through its own save readiness checks; nothing to save in entries-only mode), `Esc` discards the panel's edits while the focus stays inside it. The `Save`/`Discard` buttons name their shortcut.

### Changed

- Zone ViewModels share selection and the file catalog through narrow contracts instead of concrete neighbors: `IFileSelection`/`IEntrySelection` (single slots with change notifications) and `IAddinFileCatalog` (live rows plus rescan), implemented by the owning zones themselves — selection flows one way, list → entries. See `docs/architecture.md`, "MVVM".
- Icon consumption consolidated behind a `PackIcon` control (`PackIconKind` enum instead of `ContentControl` + `Icon.*` template at every usage site).
- Icon artwork switched to Material Design Icons paths (`refresh`, `plus`, `close`, `delete-outline`, `folder-outline`, `alert-outline`, `download`, `help`, `heart`, `earth`); the eight view-mode icons and the theme half-moon stay hand-drawn.
- Shared button and toggle styles moved from per-view copies to `Styles/Buttons.xaml`/`Styles/Toggles.xaml` (merged once in `App.xaml`); view-specific bits (wrapping margins, `IsLocked` dimming) stay as small local `BasedOn` styles.
- Shared text-field and tooltip styles moved to `Styles/Inputs.xaml`/`Styles/Tooltips.xaml` the same way.
- Theme dictionaries split into shared chrome (`Themes/Chrome/`, no application ties) and app-specific parts (`Themes/App/`, AvalonEdit highlighting), composed by thin `Themes/Light.xaml`/`Dark.xaml` entry points — first step toward a reusable theme library.

### Fixed

- Row button "Show in folder" revealed the selected file instead of the clicked row (a button click does not move the `ListBox` selection): the button now passes its own row as the command parameter, falling back to the selection without one.
- `TooltipLabelBrush` missing in the light theme: tooltip field labels fell back to the default instead of muted gray; the key now exists in both themes, and `AddinManager.Theming.Wpf.Tests` pins key parity of both dictionary pairs.

## [1.2.0] - 2026-09-22

### Added

- Row button "Show in folder": a folder icon next to the row × button (new `Icon.Folder` template in the Feather outline style) reveals its `.addin` file in Explorer (`explorer /select`), for enabled and `disabled/` files alike; read-only, works while Revit runs. New `IFolderOpener`/`ExplorerFolderOpener` behind the usual DI abstraction.

## [1.1.0] - 2026-09-21

### Added

- Plugin-list bulk selection: per-row selection checkbox (separate from the enable toggle, mirrored into `ListBoxItem.IsSelected`, `Extended` mode keeps `Ctrl/Shift/Ctrl+A`) and a bottom bulk bar (`Selected N` inline with enable/disable toggle + `Delete` + select-all toggle wrapping into two lines when narrow, locked while Revit runs). Selection survives rescans by file identity; bulk delete asks once and reports the first failure in the list banner.
- Manifest-entries bulk selection: same checkbox column (shared `Icon.Check` glyph in `Resources/Icons.xaml` — the Material Design Icons check path with a matching outline — shared `SelectionCheckBoxStyle` in `App.xaml`) with a bottom bulk bar (`Selected N` inline with select-all toggle + `Delete` wrapping into two lines when narrow — entries have no toggles, so no enable/disable); bulk delete removes all marked entries in a single file save after one confirmation, selection survives reloads by `AddInId`.

- Form zone (`FormViewModel`/`FormView.xaml`): the structured per-entry editor (plan, section 6 — "the active entry form covers the full .addin schema"), no longer a stub. Depends directly on `EntriesViewModel` (selected file + entry) and `ListViewModel` (`Refresh()` after a successful save) — the same "zones are independent, except..." exception already used elsewhere. `IManifestSchema`/`RevitManifestSchema` (`AddinManager.Core.Abstractions.Manifests`) is the version×type field table the plan asks for (section 8, "a table in Core, data — not code"); the form's `Show*` properties (`ShowText`, `ShowVisibilityMode`, ...) read it to decide which field groups `FormView.xaml` shows, and switching the `EntryType` chips ("no disabling", per the plan) re-evaluates them immediately. `VisibilityMode`/`Discipline` are chip toggles (`SelectableOptionViewModel`) rather than checkboxes, per the plan's "no plain checkboxes anywhere" rule. `AddInId` has a "Сгенерировать" button (`Guid.NewGuid()`). `Save` builds a new `AddinEntry` via `original with { ... }` (nulling any field the current type doesn't allow), substitutes it into a copy of the file's `AddinManifest.Entries` by the *original* `AddInId`, serializes with `IAddinManifestParser.ToXml`, and hands the XML to `IAddinMarkupService.Save` — the same atomic-write-plus-`.bak`-plus-revalidation path the Markup zone's raw-XML save already uses, so `AddInId` uniqueness and structural validity are checked exactly once, in one place. Researching the actual field/version matrix (Autodesk's "Add-in Registration" docs plus API history) found the plan's starting hypothesis "`DBApplication` — since `2022`" was wrong — `IExternalDBApplication` shipped in Revit 2012 — so within our 2021-2027 range every type and field is available in every version; `docs/PLAN.md` section 6 and `docs/architecture.md` ("Form zone") are corrected accordingly. Not in scope here: the file-level `ManifestSettings` isolation section (2026+, "above the entry tabs" per the plan) and a file-browse dialog for `Assembly`/image paths.
- Live sync between zones and the disk, at the user's request ("где бы ни меняли данные, они должны быть актуальны и в других окнах", "если меняем что-то в файловой системе, окно тоже обновляется"): `MarkupViewModel.Save` was found to be the one save path that never called `ListViewModel.Refresh()` afterward (the Form zone already did) — the plugin list, Entries panel and Form panel kept showing the manifest read before a raw-XML edit until someone hit "Обновить" manually; `MarkupViewModel` now takes and calls `Refresh()` too, closing that asymmetry. Separately, a new `IAddinChangeWatcher`/`FileSystemAddinChangeWatcher` (`AddinManager.Core.Abstractions.Storage`) wraps two `FileSystemWatcher`s over the same User/Machine roots `FileSystemAddinStore` scans (`IncludeSubdirectories`, so one watcher per root covers every version and its `disabled/`), debouncing bursts of raw events (temp-file-then-`File.Replace` is Created/Changed/Renamed almost at once) into a single `Changed` per 300ms window; `ListViewModel` now takes it as a constructor dependency, starts it, and calls `Refresh()` on every `Changed` — so edits made outside the app (another process, Explorer, a second copy of the manager) are picked up too, not just the app's own saves. `Changed` can fire off the UI thread, so a new `IUiDispatcher`/`WpfDispatcher` (`AddinManager.Launcher.Abstractions.Services`) marshals it before touching `ListViewModel.Files`; tests use a synchronous fake instead of a real `Dispatcher`. New `AddinManager.Launcher.Tests` project (the first to cover `AddinManager.Launcher`'s ViewModels, `net10.0-windows`/`UseWPF` since `ListViewModel` itself uses `System.Windows.Data.ListCollectionView`) with fakes (`FakeAddinStore`, `FakeAddinChangeWatcher`, `RecordingUiDispatcher`) covering the watcher wiring and, against a real `FileSystemAddinStore`/`FileAddinMarkupService` on temp folders, the Markup-save-refreshes-the-list regression; `FileSystemAddinChangeWatcherTests` (`AddinManager.Core.Tests`) cover the watcher itself against real temp folders and a real `FileSystemWatcher` (missing folders, both scopes, `disabled/`, debounce coalescing a burst into one event, silence before `Start()`/after `Dispose()`).
- Dense logging and test coverage across every service on the "update addin data" path, at the user's explicit request (плотно залогировать и покрыть тестами всё, что касается обновления данных об аддинах): `FileSystemAddinStore.SetEnabled` now logs Information on a real move succeeding (previously only the pre-move intent and post-failure error were logged) and `ScanScope` logs Debug for a missing version root and a per-scope found-count; `FileSystemAddinChangeWatcher.Start()` logs Debug on an ignored repeat call and `Dispose()` logs Information with the watcher count; `AddinFileRowViewModel.OnIsEnabledChanged` now logs Information after a successful toggle (not just before attempting it) and Debug when the `_isReverting` guard suppresses a recursive re-entry; `ListViewModel.Refresh` logs Debug per-version file counts and Information when the previously selected file didn't survive a rescan; `MarkupViewModel.Save` logs Information on success, and `FormViewModel.Save`'s two early validation rejections (bad `AddInId`, missing `Assembly`/`FullClassName`) now log Warning — previously both were silent, surfacing only through `ErrorMessage`. Catch blocks around `IAddinMarkupService.Save` deliberately stay silent in every `Save()` (Form/Markup/ManifestSettings) — `FileAddinMarkupService.Save` already logs the Warning/Error at the point the failure is known, so this avoids double-logging the same event, generalizing the reasoning behind `FileSystemAddinStore.SetEnabled`'s own "log once, wrap, don't rethrow-and-relog" comment (SonarAnalyzer S2139) from exceptions to logging. New `RecordingLogger<T>` test double (`ILogger<T>` that records level/message/exception; duplicated identically in `AddinManager.Core.Tests` and `AddinManager.Launcher.Tests`, which don't reference each other) replaces `NullLogger<T>` wherever a test needs to assert something was actually logged, not just that it behaved correctly. New/extended tests: `FileSystemAddinStoreTests` (SetEnabled success/no-op logging, ScanScope missing-folder/found-count logging), `FileAddinMarkupServiceTests` (Save's three outcomes — success/rejected/write-failure — each asserted at its own log level), `FileSystemAddinChangeWatcherTests` (repeat-`Start()` Debug log, `Dispose()` Information log), `AddinFileRowViewModelTests` (success logs Information twice — intent and result — failure logs Error plus a Debug on the suppressed revert), `MarkupViewModelRefreshTests` (Save success logs Information), `ListViewModelChangeWatcherTests` (Refresh logs Debug per-version counts and Information when a selection doesn't survive). `FormViewModel` and `ManifestSettingsViewModel` had no test coverage at all before this pass; new `FormViewModelTests`/`ManifestSettingsViewModelTests` cover their `Save()` paths (success and each validation rejection) against a real `FileSystemAddinStore`/`FileAddinMarkupService`/`RevitManifestSchema` on temp folders — the same real-integration style `MarkupViewModelRefreshTests` already established, since faking the full List → Entries → Form chain would mean re-implementing logic already covered elsewhere.
